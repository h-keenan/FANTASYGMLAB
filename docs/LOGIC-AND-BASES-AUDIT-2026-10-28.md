## Verdict in one paragraph

The core trade engine is better unified than the question fears: the signed-in Analyzer, Trade Hub, the bot feed and Trade Finder all price a trade through one pipeline (`trade_analyzer_fit` -> `trade_grade` -> `decide_offer_verdict`), Free limits come from one set of server constants, and several web/mobile TypeScript files are byte-identical with sync tests. But the web of logic is not clean at the edges. The same trade or the same player gets different numbers, words or colors on different surfaces: the public Analyzer uses its own percentage verdict and un-age-adjusted values, tier names differ between API, UI and draft board, injury tones differ between web and app, the app defaults every league to the Dynasty lens while web detects redraft, push alerts ignore the league lens, and the prices in three fallback tables are $3.99/$19.99 while live Stripe sells $9.99/$59.99. Separately, the launch bases have real holes: a Free-to-Pro self-grant through a user-writable settings row, support email on a domain with no MX record, scheduled jobs that run every 4 to 6 hours instead of every 15 to 30 minutes, nothing that pages a human, and a free-limit wall that shows a generic error.

## 1.2 What is already well unified (keep it that way)

1. **One trade pipeline.** `trade_grade.py` is shared by the Analyzer, Trade Hub, Finder and the bot (`external_interesting_trades.Context.evaluate` at line 225 calls `evaluate_trade_analyzer_fit` then `decide_offer_verdict`). A Hub idea and an Analyzer run of the same package grade identically. Counter packages are regraded through the same path.
2. **Free vs Pro limits are numbers in code, not copy.** `premium_benefits.premium_comparison()` builds the paywall rows from the real constants (`MAX_LEAGUES_FREE`, `MAX_TARGETS_FREE/PREMIUM`, `FREE_VISIBLE_IDEAS`, `FREE_NEXT_MOVE_ITEMS`). `freeLimits.ts` carries no numbers of its own; web and app copies are byte-identical and a test enforces it (`freeLimits.test.ts:45`). Tests tie rows to constants (`tests/test_premium_conversion_intent_flow.py:80`).
3. **Server-side enforcement.** Trade-idea pool, ad unlocks, league claims and weekly Analyzer evaluations live in Redis keyed by authenticated user (`free_tier_ledger.py`), not in client-writable settings (closed in #1390).
4. **Trial length** has one constant (`supabase/functions/_shared/config.ts:10`), served by `billing-plans` as `trial_days`; the web fallback (`landingTrial.ts:10`) and Python default are only offline fallbacks.
5. **Byte-identical web/app TypeScript with tests**: `freeLimits`, `deadlineMode`, `experienceCopy`, `verdictTrust`, `dashboardLayout`, `premiumComparison`, `sampleLeague`, `startHere`, `sleeperConnectErrors`, `matchupPlanner`.
6. **Deadline logic** is derived from one function (`league_calendar.weeks_to_deadline`) for dashboard, plan and push.
7. **Experience-level (beginner) copy** is one file mirrored web/app; its tier-percentage sentence matches `player_tiers.py` thresholds (.992/.975/.94/.84/.66).
8. **Canonical share words** (`TRADE_SHARE_COPY`) are tested equal between web and mobile.
9. **Legal text** is exported from one source into both clients with tests.
